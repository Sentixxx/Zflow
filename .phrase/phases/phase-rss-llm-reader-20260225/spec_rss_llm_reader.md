# SPEC: RSS + LLM Reader (Phase 1)

## Summary
构建一个开源、自托管 RSS 阅读器（RSS/Atom only），提供 LLM 驱动的内容评分、分类与探索内容注入，以降低信息过载并缓解信息牢房。

## Goals
- 提供可用的基础阅读器能力：订阅、阅读、收藏、过滤、分类。
- 提供面向推荐链路的统一摘要层：原始摘要、规范化摘要、记忆摘要职责分离。
- 提供多维评分：质量、相关性、新颖性（辅以文笔、反响信号）。
- 提供可控探索机制：默认 1%，用户可调、可关闭。
- 提供可解释推荐：展示分类与推荐依据。
- 提供偏好档案：允许用户手动编辑并参与推荐提示。
- 让推荐系统可演进为带记忆的智能体：基于摘要资产与用户交互沉淀长期记忆。
- 交付形态覆盖 Web + PWA + 打包应用。
- 后端统一使用 Go 实现 API、抓取与调度能力。
- 默认零遥测，不进行集中数据采集。

## Non-goals
- 首版不接入非 RSS/Atom 来源（如平台 API 深度集成）。
- 首版不做中心化 SaaS 托管服务。
- 首版不以商业化指标作为成功标准。

## Technical Constraints
- 后端语言固定为 Go。
- 前后端通过 HTTP API 解耦，前端不得直接依赖抓取逻辑。

## User Flows
1. 导入订阅源
- 操作：用户添加 RSS/Atom URL。
- 反馈：成功抓取并显示订阅内容。
- 回退：抓取失败时提供错误信息与重试。

2. 阅读与筛选
- 操作：用户浏览主信息流，按分类/标签/分数过滤。
- 反馈：高价值内容优先展示，低价值内容可降权。
- 回退：用户可切换为时间排序。

3. 探索比例调节
- 操作：用户通过滑块调节探索比例（默认 1%）。
- 反馈：主流中随机掺入跨偏好内容。
- 回退：用户可设置为 0% 完全关闭。

4. 偏好档案编辑
- 操作：用户修改偏好关键词/主题倾向。
- 反馈：后续评分与推荐受新偏好影响。
- 回退：支持重置为默认偏好。

5. 推荐解释
- 操作：用户查看某条内容“为什么推荐”。
- 反馈：展示分类、核心维度与触发信号。
- 回退：用户可标记“减少此类内容”。

6. 摘要与记忆沉淀
- 操作：系统在文章抓取或正文抽取后生成规范化摘要与记忆摘要。
- 反馈：推荐链路可复用统一摘要，并根据用户打开/收藏/减少此类内容等行为更新记忆。
- 回退：AI 摘要失败时回退到原始摘要，不阻塞阅读。

## Edge Cases
- 源内容质量极差导致评分失真。
- 外部反响信号不可用时的评分降级策略。
- 高频重复内容跨多个源重复出现。
- 用户偏好极端收窄导致探索内容体验下降。
- 大量订阅下抓取/排序性能退化。
- AI 摘要失败或漂移导致记忆污染。
- 只有 RSS 原始摘要、缺失正文时的降级质量波动。

## Acceptance Criteria
- 可成功添加并读取 RSS/Atom 源。
- 主信息流支持排序、分类、收藏和基础过滤。
- 每条内容可输出评分与分类。
- 推荐管线可读取统一摘要资产，而非直接依赖 RSS 原始摘要字段。
- 在真实评分管线接入前，前端可基于文章内容生成临时启发式分数，并支持按质量/相关性/新颖性/综合分排序。
- 后端列表接口在真实评分管线接入前，需先输出同结构的启发式推荐分数并支持按 `sort` 参数稳定排序。
- 后端需在文章入库和正文刷新后持久化质量/相关性/新颖性/总分，供列表、详情和后续推荐解释复用。
- 对历史文章若缺少第一阶段评分特征，列表或详情首次读取时需自动补写 `article_features` 与镜像分数，避免旧数据长期停留在兼容计算路径。
- 后端第一阶段评分重构已采用分层规则管线：输入门控与 Readability 兜底、单篇规则特征、最近文章池近重复新颖度与融合排序，并保持 `recommendation_scores` 对外结构稳定；LLM 结构化标签留待下一阶段接入。
- 前端开发联调需支持局域网访问：Vite 开发服务监听所有网卡，默认 API Base 依据当前浏览器 hostname 推导为 `http://<host>:8080`，同时保留用户保存的自定义 API Base 覆盖。
- 探索比例滑块可实时生效，支持设置为 0%。
- 用户可编辑偏好档案并影响推荐结果。
- 用户关键行为可沉淀到记忆层，并可用于后续推荐解释。
- 推荐项可展示“推荐依据”。
- Web 与 PWA 均可运行；打包应用可安装并打开。
- 默认配置下无集中遥测上报。

## Success Signals
- 社区指标：GitHub Stars、Issues、PRs。
- 本地验证：实例内本地统计（可关闭）与用户主观满意度。
